# 할 일

2026-10-31 · v2.1.0 기준

아직 풀지 않은 문제, 사람이 직접 해야 하는 점검, 다음 기능 후보를 모은다. 기능을 고르면 CLAUDE.md 순서(SRS → SDD → 구현 → 검증 → 배포)로 진행하고, 끝낸 항목은 여기서 지운다(한 일은 릴리스 노트에 남는다).

## 1. 미해결

- [ ] **보안 의존성 올리기**: 2026-10-31의 `npm audit` 결과다. 버전을 올리고 단위·E2E를 다시 돌려 patch 릴리스로 낸다.
    - dompurify 3.4.16 이하: critical. viewer.html에 묶여 미리보기 정제에 쓰인다.
    - markdown-it 15.0.0~15.0.2: high. viewer.html에 묶여 있다. 인라인 HTML·링크 참조 정의에서 처리 시간이 제곱으로 는다.
    - undici 7.30.0 이하: high. jsdom을 거쳐 들어온 테스트 전용 의존성이다.
- [ ] **E2E 간헐 실패 "원문 보기도 바뀐 줄을 표시"(FR-WATCH-05)**
    - 증상: 네 번 돌려 한 번, 표시된 줄 없이 실패했다.
    - v2.1.0 조치: 줄이 그려질 때까지 기다리게 하고, 실패하면 바뀐 곳·보기 모드·편집기 뷰포트·그려진 줄 수를 남긴다.
    - 할 일: 다시 실패하면 그 진단으로 원인을 확정한다.
- [ ] **E2E 간헐 실패 "뷰어 탭 합치기"(FR-FILE-04)**
    - 증상: v1.2.0 개발 중 다섯 번 중 두 번, 3초 제한에 걸렸다. 최근 실행에서는 모두 통과했다.
    - 원인을 찾지 못했다. 실패하면 남기는 진단(활성 탭, 문서 상태, SSE 상태)을 보고 원인을 확정한다.
- [ ] **넘겨받기가 막힐 때 두 탭이 어긋남**
    - 상황: 실행기 모드에서 이전 뷰어 탭에 저장하지 않은 편집이 있으면 그 탭이 물러나지 않는다.
    - 문제 1: 그 알림이 뒤에 있는 이전 탭에 뜬다.
    - 문제 2: 새 탭은 같은 파일의 디스크 내용을 열어, 두 탭이 다른 내용을 보인다(`web/src/app.ts` joinViewers).

## 2. 수동 점검

자동 테스트로 확인하지 못한 것이다. 릴리스마다 알려진 제한에 적어 왔다.

- [ ] **인쇄**: 실제 종이·PDF 인쇄(다크 테마 포함, 다이어그램 색), 인쇄 대화상자. E2E는 인쇄 스타일과 테마 바꾸기만 본다.
- [ ] **한글 입력기**: 실제 입력기로 찾기 칸에서 조합 중 Enter를 누르는 경우. E2E는 조합 중 keydown을 합성해서만 본다.
- [ ] **브라우저**
    - Chrome·Firefox·Safari에서 열기·렌더링·찾기·보기 모드를 본다.
    - Firefox·Safari에서 내려받기 저장과 위치 복사(Shadow DOM 선택)를 본다.
    - 화면 배율 100~200%를 눈으로 본다.
- [ ] **독립 모드**
    - 파일·폴더 선택 대화상자와, 다음 실행 때 권한을 다시 받는 흐름
    - 실제 쓰기 권한 창(E2E는 거절한 경우만 본다)
    - 폴더 끌어다 놓기(CDP로 흉내 낼 수 없음)
- [ ] **Windows 앱**
    - 탐색기에서 더블클릭과 "연결 프로그램" 흐름
    - 모니터를 옮길 때의 DPI, 어두운 제목 표시줄
    - WebView2 런타임이 없는 PC의 안내 창
    - Windows 종료 중 저장 확인
    - ARM64
- [ ] **실행기·스킬**
    - 실제 Claude Code 대화에서 스킬이 골라지는지, 위치를 붙여 여는지
    - 사용자가 뷰어에서 고치던 파일을 Claude가 고칠 때의 충돌 흐름
    - Windows에서 직접 돌린 실행기(드라이브·네트워크 공유 경로)
    - macOS·Linux, Node.js 18

## 3. 개선안 P2

2026-10-30 사용자 use case 검토에서 나온 것 가운데 v2.1.0에 넣지 않은 것이다. 규모는 소·중·대로 적었다.

- [ ] **폴더에서 찾기**(Ctrl+Shift+F, FR-FIND-04, 대): 문서 묶음(docs 폴더)에서 내용으로 찾지 못한다. 단축키만 잡혀 있다.
- [ ] **빠른 열기·뒤로·앞으로**(중)
    - 빠른 열기는 Ctrl+Shift+O(FR-NAV-06), 뒤로·앞으로는 Alt+←/→(FR-NAV-04)다.
    - 링크를 따라가면 탭이 늘 탭 줄 끝에 생기고 돌아갈 방법이 없다. 링크로 연 탭은 지금 탭 옆에 둔다.
- [ ] **저장하지 않은 편집 복구**(신규, 중)
    - 문제: 브라우저나 앱이 갑자기 끝나면 고친 내용을 잃는다. 자동 저장은 기본 꺼짐이다.
    - 할 일: 세션에 초안을 두고, 다시 열 때 복구할지 묻는다.
- [ ] **작업 목록 체크박스로 원문 고치기**(신규, 소~중): Claude 보고서의 할 일 목록을 그 자리에서 체크한다. 수정됨으로 표시하고, 저장은 사용자가 한다.
- [ ] **미리보기에서 편집으로 가는 길**(FR-VIEW 보강, 중)
    - 미리보기를 더블클릭하면 분할 보기에서 그 줄의 원문을 연다.
    - 미리보기에서 편집 키(Ctrl+H, 실행 취소)를 누르면 지금은 아무 일도 없다. 원문 보기로 바꾸라고 안내한다.
- [ ] **Windows 앱 표준 단축키**(FR-DESK 보강, 소)
    - 앱은 브라우저 단축키를 끄므로 Ctrl+W, Ctrl+Tab, Ctrl+Shift+Tab, Ctrl+N, Ctrl+Shift+T를 쓸 수 있다.
    - 지금은 브라우저용 우회 키(Alt+W 등)만 있다.
- [ ] **오류 알림 남기기**(NFR-USE, 소): 알림은 4초 뒤 사라져 긴 안내와 오류를 놓친다. 오류는 닫을 때까지 남기고 × 단추를 단다.
- [ ] **미리보기 찾기가 서식 경계를 넘게**(FR-FIND-03, 중): 지금은 글 노드 하나 안에서만 찾아, 굵게·링크·인라인 코드에 걸친 문구를 찾지 못한다(`web/src/views/preview.ts` find).
- [ ] **최근 파일의 읽던 위치 기억**(FR-FILE-06 보강, 소): 최근 파일을 다시 열면 맨 위부터 보인다.

## 4. 개선안 P3

- [ ] **GitHub 알림 블록**(`> [!NOTE]` 등, 신규, 소): 지금은 그냥 인용문으로 보인다.
- [ ] **수식**(`$…$`, `$$…$$`, FR-REN-06, 중): KaTeX를 넣으면 크기 상한(viewer.html 3.5 MiB, NFR-PORT-03)과 맞춰 봐야 한다.
- [ ] **내보내기**(FR-EXP-02~04, 중~대): HTML·PDF 내보내기와 서식 있는 복사. 뷰어가 없는 동료에게 보낼 때 쓴다.
- [ ] **서식 단축키와 이미지 붙여넣기**(신규, 중): Ctrl+B를 왼쪽 패널 토글이 쓰고 있어, 굵게 단축키와의 충돌을 먼저 정리해야 한다.
- [ ] **`mdview --where`**(신규, 중): Claude가 사용자가 지금 보는 문서·제목을 알 수 있게 한다. 뷰어가 실행기에 현재 위치를 알려야 한다.
- [ ] **큰 문서 분할 보기의 부분 갱신**(NFR-PERF-08, 대): 1 MB 문서에서 미리보기를 다시 그리는 동안 입력이 밀린다(키 입력 최대 438 ms). 블록 단위로 갱신한다.
- [ ] **한글 줄 바꿈 설정**(신규, 소): 본문이 어절 중간에서 줄을 바꾼다. `word-break: keep-all`을 설정으로 고르게 한다.
